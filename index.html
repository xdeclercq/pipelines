Pipelines

Un jeton fine-grained (GitHub → Settings → Developer settings → Fine-grained tokens), limité aux dépôts tabula, outsmart et ticket-scanner, avec une date d’expiration et les permissions Actions : lecture et écriture, Contents : lecture, Deployments : lecture. Il reste dans ce navigateur et n’est envoyé qu’à GitHub.

Comment ça marche

La vue d’ensemble donne, pour chaque appli, la version en QA et en prod (web 🌐, Android 📱) : ✓ si elle est à jour avec main, sinon son retard en commits (−3) ; le nom ouvre son pipeline. Dans le pipeline d’une appli, chaque ligne est une version (un commit de main) : les 3 dernières, et celles en QA et en prod. 🌐 web, 📱 Android. Chaque push passe seul l’étape de commit et le web en QA (tests d’acceptation compris) ; ▶ QA y ajoute l’app Android pour les testeurs ; ▶ Prod publie web et Android. Un bouton n’apparaît que pour une version qui a passé les étapes précédentes, à la place de l’étape qu’il lance : pas encore faite, ou en échec (cadre rouge, pour réessayer). Revenir à une version déjà déployée se fait dans GitHub : Actions → le workflow → Run workflow, avec son sha.

réussi échec en cours en attente annulé pas encore — sous l’icône, la durée (ou le temps écoulé).
